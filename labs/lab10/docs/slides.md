# Слайди (10 штук, 75–90 хв)

## 1. Навіщо Observability + різниця з Monitoring
- **Навіщо:** швидко відповідати на нові питання в проді й зменшувати MTTR.
- **Що показати:** дві колонки «Monitoring vs Observability», приклад «чому p99 росте лише ввечері на /orders?». Пояснення «симптом → діагноз → лікування».
- **Повідомлення:** Observability = здатність досліджувати невідоме без нового релізу; кореляція сигналів; контроль інцидентів.

## 2. SDLC + SLI/SLO/SLA, Error Budget & Burn Rate
- **Навіщо:** спостережність закладаємо під час дизайну; формуємо мову компромісів.
- **Що показати:** стрічка SDLC (ідея → дизайн → реалізація → тест → деплой → експлуатація → фідбек) + таблиця SLI/SLO/SLA/Error Budget/Burn rate.
- **Меседж:** плануємо якість заранее, рішення базуються на даних.

## 3. Три стовпи, RED і Golden Signals
- **Навіщо:** пов’язати метрики, трейси та логи в єдиний ланцюжок «симптом → причина».
- **Що показати:**
  - Метрики: RPS, error rate, p95/p99, saturation CPU/БД/черг.
  - Трейси: шлях `http.server → svc A → svc B → db.query`.
  - Логи: JSON із `trace_id`.
  - Швидкий RED (Rate/Errors/Duration) і Golden signals (latency/traffic/errors/saturation).

## 4. Логи: структура, кореляція, анти‑патерни
- **Навіщо:** зробити логи машинно-читабельними та безпечними.
- **Що показати:** «поганий» рядок проти структурованого JSON з полями `service`, `env`, `route`, `status`, `duration_ms`, `trace_id`, `span_id`, `msg`. Окремо — правила PII/маскування.

## 5. Метрики: counter/gauge/histogram + PromQL
- **Навіщо:** побачити тренди, позбудитись шуму в алертах, будувати SLO.
- **Що показати:** різниця counter/gauge/histogram, `histogram_quantile` для p95, базові запити RED, поради щодо лейблів і кардинальності.

## 6. Трейсинг: як читати і що шукати
- **Навіщо:** локалізувати вузькі місця та n+1.
- **Що показати:** дерево спанів, атрибути (`db.system`, `net.peer.name`, `http.route`), події `exception.*`, W3C `traceparent`/`tracestate`, прокидання `trace_id` у логи.

## 7. OpenTelemetry SDK/Auto + кореляція
- **Навіщо:** швидко стартувати без вендор-локіну.
- **Що показати:** автоінструментації HTTP/DB, ручні спани на гарячих ділянках, передача контексту в логи через OTel.

## 8. OTel Collector: pipeline/вартість/шум
- **Навіщо:** централізовано керувати політиками без редеплоя сервісів.
- **Що показати:** `receivers → processors → exporters`, приклади `memory_limiter`, `k8sattributes`, `attributes` (маскування), `transform` (нормалізація маршрутів), `tail_sampling` (ERROR/p99), `routing` (prod/stage).

## 9. Kubernetes + Mesh/Ingress + Дашборди/Алерти
- **Навіщо:** отримати базову телеметрію з коробки, показати здоров’я периметра і алерти на burn rate.
- **Що показати:** readiness/liveness/startup, `/ready` з реальними перевірками, метрики периметра, ретраї/таймаути/бюджет ретраїв, мінімальний RED-дешборд, burn-rate алерти та рунабук.

## 10. Кейс + Мінідемо + CI/CD + Домашка
- **Навіщо:** зв’язати все в е2е історію.
- **Що показати:** сценарій «p95 ввечері», Node.js + OTel + Collector, перевірка `/metrics` і SLI в пайплайні, домашка: RED + трейси + 3 алерти + 1 рунабук.
