# Roadmap: Zhuzhyk

| Тиждень | Ціль | Що реалізуємо |
|---|---|---|
| 1 | Базовий стенд | Клієнт → Express → SQLite, `GET /items`, форки та pull requests *(виконано)* |
| 2 | Документація | Бізнес-документ, архітектурна діаграма, roadmap |
| 3 | Доменна модель | Піддомени (каталог, користувачі, замовлення, оплата), глосарій, контекстна карта; новий endpoint `GET /items/:id` та `POST /items` |
| 4 | Контракт API та CRUD | `openapi.yaml`, Swagger Editor, CRUD для товарів, ADR, `GET /health`, юніт-тести |
| 5 | Стійкість та базова авторизація | Реєстрація/вхід, ролі (покупець/адмін); єдиний формат помилок, `X-Request-Id`, ідемпотентність `POST /orders`, ретраї й таймаути на клієнті |
| 6+ | Інфраструктура | Docker/docker-compose, CI/CD, observability, Kubernetes |

## Найближчі 3–4 тижні детальніше

**Тиждень 3**
- Додати `GET /items/:id` та `POST /items` (валідація вхідних даних).
- Оформити `docs/domain/` (сутності, глосарій, контекстна карта).

**Тиждень 4**
- Описати контракт у `docs/api/openapi.yaml` і перевірити в Swagger Editor.
- Реалізувати повний CRUD товарів за шарами `api/ → service/ → domain/`.
- Написати мінімум 2 юніт-тести для сервісного рівня.

**Тиждень 5**
- Базова авторизація (реєстрація, вхід, хешування паролів, ролі).
- Кошик і замовлення (`POST /orders` з `Idempotency-Key`).
