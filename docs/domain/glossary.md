
# Глосарій предметної області «Жужик»

## 1. Загальні терміни

| Термін | Англійська назва | Опис |
|---|---|---|
| Жужик | Zhuzhyk | Вебзастосунок для перегляду товарів та оформлення замовлень |
| Предметна область | Domain | Бізнес-процеси та правила, які описує система |
| Обмежений контекст | Bounded Context | Частина системи з власними сутностями та правилами |
| Доменна сутність | Entity | Об'єкт предметної області з унікальним ідентифікатором |
| Модульний моноліт | Modular Monolith | Єдиний застосунок, розділений на логічні модулі |

## 2. Каталог товарів (Catalog)

| Термін | Англійська назва | Опис |
|---|---|---|
| Каталог | Catalog | Сукупність товарів, доступних для перегляду |
| Товар | Product | Окрема позиція каталогу |
| Ідентифікатор товару | Product ID | Унікальний номер товару |
| Назва товару | Name | Найменування товару |
| Опис товару | Description | Інформація про товар |
| Ціна | Price | Вартість одиниці товару |
| Залишок | Stock | Кількість доступних одиниць товару |

## 3. Замовлення (Orders)

| Термін | Англійська назва | Опис |
|---|---|---|
| Замовлення | Order | Запит покупця на придбання товарів |
| Позиція замовлення | Order Item | Конкретний товар і його кількість у замовленні |
| Загальна вартість | Total Price | Сума вартості всіх позицій |
| Статус замовлення | Order Status | Поточний етап обробки замовлення |

## 4. Користувачі (Users)

| Термін | Англійська назва | Опис |
|---|---|---|
| Користувач | User | Особа, яка взаємодіє із системою |
| Покупець | Customer | Користувач, який оформлює замовлення |
| Адміністратор | Administrator | Користувач, який керує каталогом |
| Роль | Role | Набір дозволених дій користувача |

## 5. Оплата та доставка

| Термін | Англійська назва | Опис |
|---|---|---|
| Платіж | Payment | Операція оплати замовлення |
| Статус платежу | Payment Status | Стан обробки платежу |
| Доставка | Delivery | Процес передавання замовлення покупцю |
| Адреса доставки | Delivery Address | Місце отримання замовлення |

## 6. Технічні терміни

| Термін | Опис |
|---|---|
| REST API | Інтерфейс взаємодії клієнта із сервером через HTTP |
| CRUD | Create, Read, Update, Delete — створення, читання, оновлення та видалення |
| DTO | Об'єкт для передавання даних між компонентами системи |
| SQLite | Локальна реляційна база даних |
| OpenAPI | Специфікація для опису HTTP API |
| DDD | Domain-Driven Design — проєктування програмного забезпечення на основі предметної області |

## 7. Узгодження назв

У доменній моделі використовується назва `Product`.

У поточній реалізації API використовується маршрут `/items`, а в SQLite — таблиця `items`.

Ці назви позначають товари каталогу. Під час реалізації CRUD необхідно узгодити назви маршрутів, моделей та DTO між учасниками команди.
