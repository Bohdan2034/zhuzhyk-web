
# Доменні сутності системи «Жужик»

## 1. Загальний опис

«Жужик» — вебзастосунок для перегляду каталогу товарів та оформлення замовлень.

Система проєктується за принципами Domain-Driven Design (DDD).

Архітектура — модульний моноліт.

## 2. Обмежені контексти (Bounded Contexts)

### Catalog — Каталог товарів
Відповідає за зберігання, перегляд та керування товарами.

Основна сутність: Product.

### Orders — Замовлення
Відповідає за створення та обробку замовлень.

Основна сутність: Order.

### Users — Користувачі
Відповідає за облікові записи користувачів.

Основна сутність: User.

### Payments — Оплата
Відповідає за облік платежів.

Основна сутність: Payment.

### Delivery — Доставка
Відповідає за інформацію про доставку замовлень.

Основна сутність: Delivery.

## 3. Доменні сутності

### Product — Товар

| Атрибут | Тип | Опис |
|---|---|---|
| id | integer | Унікальний ідентифікатор |
| name | string | Назва товару |
| description | string | Опис товару |
| price | number | Ціна товару |
| stock | integer | Кількість товару на складі |

Правила:
- Назва товару не може бути порожньою.
- Ціна не може бути від'ємною.
- Кількість на складі не може бути від'ємною.

### Order — Замовлення

| Атрибут | Тип | Опис |
|---|---|---|
| id | integer | Ідентифікатор замовлення |
| userId | integer | Ідентифікатор користувача |
| items | array | Список позицій замовлення |
| totalPrice | number | Загальна вартість |
| status | string | Статус замовлення |

### User — Користувач

| Атрибут | Тип | Опис |
|---|---|---|
| id | integer | Ідентифікатор |
| name | string | Ім'я користувача |
| email | string | Електронна пошта |
| passwordHash | string | Хеш пароля |
| role | string | Роль користувача |

### Payment — Платіж

| Атрибут | Тип | Опис |
|---|---|---|
| id | integer | Ідентифікатор платежу |
| orderId | integer | Ідентифікатор замовлення |
| amount | number | Сума платежу |
| status | string | Статус платежу |

### Delivery — Доставка

| Атрибут | Тип | Опис |
|---|---|---|
| id | integer | Ідентифікатор доставки |
| orderId | integer | Ідентифікатор замовлення |
| address | string | Адреса доставки |
| status | string | Статус доставки |

## 4. Контекст для CRUD

Для практичної роботи №4 обрано контекст Catalog.

Основна сутність — Product.

Заплановані операції:
- Створення товару.
- Отримання списку товарів.
- Отримання товару за ID.
- Оновлення товару.
- Видалення товару.

Поточна реалізація використовує SQLite-таблицю items з полями id та name.

Розширена модель Product з полями description, price та stock є запланованою і потребує відповідних змін у базі даних та API.
