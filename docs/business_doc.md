# Бізнес-документ: Zhuzhyk

## 1. Назва системи та короткий опис

**Zhuzhyk** — невеликий онлайн-магазин (курсовий командний проєкт), де покупці можуть переглядати каталог товарів, додавати їх до кошика та оформлювати замовлення, а адміністратор керує асортиментом і замовленнями.

Система реалізується як веб-застосунок за схемою «браузер (`frontend/`) → бекенд (`backend/`, REST API) → база даних». На першому етапі використовується Node.js/Express та SQLite; архітектура закладається так, щоб надалі можна було додати автентифікацію, сповіщення та онлайн-оплату.

Мета проєкту — не лише зробити працюючий магазин, а й пройти повний цикл сучасної розробки: від документації та проєктування домену до контейнеризації, CI/CD і моніторингу.

## 2. Користувачі (ролі)

| Роль | Опис | Основні можливості |
|---|---|---|
| **Гість** | Неавторизований відвідувач | Перегляд каталогу, пошук, реєстрація/вхід |
| **Покупець** | Зареєстрований користувач | Кошик, оформлення замовлення, історія замовлень |
| **Адміністратор** | Співробітник магазину | Керування товарами, категоріями, статусами замовлень |

## 3. Основні сценарії використання

1. **Перегляд каталогу.** Гість відкриває сайт, бачить список товарів, фільтрує за категорією та відкриває картку товару.
2. **Реєстрація та вхід.** Гість створює акаунт (email + пароль) і входить у систему.
3. **Оформлення замовлення.** Покупець додає товари до кошика, вказує дані доставки та підтверджує замовлення.
4. **Перегляд історії замовлень.** Покупець бачить список своїх замовлень і їхні статуси.
5. **Керування асортиментом.** Адміністратор додає, редагує та видаляє товари, змінює статус замовлення (нове → оплачене → відправлене → доставлене).

## 4. Функціональні вимоги

- FR-1. Система повертає список товарів та деталі окремого товару.
- FR-2. Система підтримує пошук і фільтрацію товарів за категорією та ціною.
- FR-3. Користувач може зареєструватися, увійти та вийти з системи.
- FR-4. Покупець може додавати/видаляти товари в кошику та змінювати кількість.
- FR-5. Покупець може оформити замовлення з кошика.
- FR-6. Покупець бачить історію своїх замовлень.
- FR-7. Адміністратор виконує CRUD над товарами та змінює статуси замовлень.
- FR-8. Система надсилає сповіщення про зміну статусу замовлення (майбутній модуль).
- FR-9. Система підтримує онлайн-оплату замовлення (майбутній модуль).

## 5. Нефункціональні вимоги

- **Швидкодія:** відповідь API на читання — до 500 мс за нормального навантаження; сторінка каталогу завантажується до 2 с.
- **Безпека:** паролі зберігаються лише у вигляді хешу; доступ до адмін-функцій тільки за роллю; захист від SQL-ін'єкцій (параметризовані запити); секрети не потрапляють у репозиторій (`.env` у `.gitignore`).
- **Зручність:** інтерфейс українською, адаптивна верстка для телефону та десктопа.
- **Надійність:** єдиний формат помилок API, ендпоінт `GET /health` для перевірки стану.
- **Підтримуваність:** код розділений на шари/модулі; документація та API-контракт (OpenAPI) ведуться разом із кодом.
- **Відтворюваність:** запуск проєкту з нуля за інструкцією з README (згодом — через Docker).

## 6. Обмеження (чого система точно не робитиме)

- Не буде власної складної логістики та інтеграції з службами доставки (лише введення адреси).
- Не буде мобільного застосунку — лише веб.
- Не буде багатомовності, мультивалютності та маркетплейс-функцій (кілька продавців).
- Не буде рекомендаційної системи та аналітики поведінки користувачів.
- Реальні платежі в межах курсу не проводяться — оплата працюватиме в тестовому (sandbox/імітаційному) режимі.
