# Практична робота №9 — Теоретична схема Kubernetes-додатку «Жужик»

«Жужик» — навчальний вебзастосунок інтернет-магазину, яким користуються покупці для перегляду товарів і оформлення замовлень. У теоретичній архітектурі його API працює в Kubernetes-кластері у namespace `zhuzhyk-prod`, а Deployment `zhuzhyk-api` підтримує дві репліки Pod-ів для базової відмовостійкості. Запити до умовного домену `shop.example.com` проходять через DNS, Load Balancer та Ingress, який маршрутизує шлях `/api` до внутрішнього Service `zhuzhyk-api` типу ClusterIP, а той розподіляє трафік між Pod-ами. Код зберігається у GitHub, GitHub Actions теоретично виконує CI/CD та збирає Docker-образ, який публікується в GitHub Container Registry (GHCR). Під час запуску Pod-и отримують образ із registry, після чого застосунок стає доступним через зазначений ланцюжок маршрутизації.

> Домен, тег образу, конфігурація Kubernetes і публікація образу в GHCR наведені як **теоретичний приклад**, а не як уже розгорнута інфраструктура.
