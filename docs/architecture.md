# Архітектура вебзастосунку «Жужик»

Файл діаграми: [`architecture_diagram.drawio`](architecture_diagram.drawio). Його можна відкрити та змінити у [diagrams.net](https://app.diagrams.net/).

## Поточна архітектура (суцільні лінії)

- **Client (Browser)** — HTML-сторінка та JavaScript у `frontend/public/`. Користувач натискає кнопку завантаження, після чого клієнт надсилає запит до API та відображає список елементів.
- **Backend (Node.js / Express)** — сервер у `backend/server.js`. Обслуговує статичну сторінку та HTTP API `GET /items` і `GET /items/:id`, повертає дані у JSON.
- **Database (SQLite)** — локальна база з таблицею `items` (`id`, `name`) та тестовими записами. З базою працює бекенд; браузер не підключається до неї напряму.

**Потік даних:** браузер → HTTP-запит → Express → SQL-запит до SQLite → JSON-відповідь → відображення у браузері.

## Заплановані компоненти (пунктирні лінії)

- **Auth Module** — автентифікація користувачів та перевірка ролей.
- **Notifications Module** — сповіщення про події в системі.
- **Payments Module** — навчальна імітація оплати або тестова інтеграція, якщо буде потрібна у наступних практичних.

Ці три модулі **ще не реалізовані**. На діаграмі вони показані як можливе розширення системи. Спочатку їх можна додати як внутрішні модулі бекенду, без переходу до мікросервісів.
